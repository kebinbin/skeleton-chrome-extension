# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## Selected direction and durable feedback

- Recreate the first generated direction: a light, neutral editorial landing page with the integrated coding workbench as the primary visual.
- The Full visualization mode must always use the current colored overlay screenshot.
- Preserve every source screenshot's original aspect ratio. Never stretch, squash, or force screenshots into a mismatched crop.
- Do not reuse the older extension video or screenshots from the portfolio repository.
- Use only fresh captures produced from the current extension version.
- The code shown beside the visualization and the rendered page must come from the same current portfolio version. Do not pair newer source with the older deployed portfolio.
- Keep the website chrome polished, minimal, and neutral; the colorful retro palette belongs inside Skeleton Layout's visualization output.
